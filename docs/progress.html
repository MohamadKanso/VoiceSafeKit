Project progression

What broke, what changed and what is fixed now.

VoiceSafeKit has been improved through real testing. This page keeps the project history visible so the work reads like an evolving open-source tool, not a single polished snapshot.

Current phase Phase 0.6

Reach and real speech: Open WebUI and LiteLLM adapters, audio bleeping, Whisper number formatting and a held-out real-speech benchmark.

Latest additions 98% on unseen speech

On a held-out set spoken by a new voice and transcribed by a bigger Whisper model, 0.6 protects 106 of 108 PII utterances. Presidio: 70.

Resolved history

Fix log

01
Resolved

Recording saved audio but did not create a transcript.

The first recorder version captured audio but did not reliably turn speech into text. That made the demo look broken because users had to type the transcript manually after recording.

Fixed by adding browser-based Whisper transcription with Xenova/whisper-tiny.en. The browser now records the clip, transcribes it after stop and places the words into the transcript box.

02
Resolved

Card numbers were sometimes treated like phone numbers.

Long digit sequences overlapped with the phone detector, so a card number test could be reported as a phone number.

Fixed by adding card-shaped number checks, card context words such as card, debit, credit and payment, plus overlap priority so payment card results win over phone results.

03
Resolved

The interface looked messy and hard to scan.

Early UI versions made the tool harder to understand than the logic itself. Capture, Check and Protect were not clear enough as a workflow.

Fixed by rebuilding the interface around sharp neon green panels, thin typography, clear step numbers and a cleaner two-column demo with the protected transcript below.

04
Resolved

The project needed visible phase history.

Because the repo was worked on repeatedly, it needed a way to show how each improvement built on the last instead of replacing the story.

Fixed by adding CHANGELOG.md, phase labels and this Progress page.

05
Resolved now

Repeated emails produced duplicate warning cards.

A realistic account recovery transcript contained two email addresses. The engine correctly found both, but the UI repeated the same email warning twice, which made the result noisy.

Fixed by grouping repeated finding types. The UI now says 2 email addresses once, while the safe transcript still redacts both addresses individually.

06
Resolved now

Natural password speech was not always flagged.

A phrase like “my password was something like WinterSecure!2026” sounded natural, but the original rule was too narrow and could miss partial password mentions.

Fixed by expanding credential detection for phrases like was, might be, could be, maybe, possibly and something like. The result is now shown as Password or secret / high.

07
Resolved now

Partial card references were not flagged.

The account recovery transcript included “my card ends in 4821”. The old detector only looked for full 13-19 digit card-like numbers, so partial card details were missed.

Fixed by adding a partial card reference detector for phrases such as card ends in, card ending with and last four digits. The UI now includes this as a separate warning type.

08
Resolved

Long transcripts needed a denser warning panel.

As more detectors were added, the Check panel could become too tall and hard to scan.

Fixed by adding compact totals for flags, grouped warning types and high-risk groups. Longer transcripts now get a scrollable warning list.

Phase 0.3, 3 June 2026

Intelligence and context

09
Shipped 3 Jun 2026

Critical PII was missing: SSNs, IBANs and CVV codes.

The original detector set covered emails, phones and payment card numbers but missed government-issued identity numbers, bank account IBANs and card security codes. Those are high-value targets for identity theft and financial fraud.

Fixed by adding three critical-severity detectors. The SSN detector excludes invalid area codes (000, 666 and 900-999). The IBAN detector runs a full mod-97 checksum to reject false positives. The CVV detector is keyword-triggered and requires a 3-4 digit number adjacent to CVV/CVC terminology.

10
Shipped 3 Jun 2026

Dates of birth and IP addresses were not flagged.

Issue #3 was previously assigned to an external contributor. Both detectors are now part of the core engine. Date of birth handles natural speech patterns ("born on March 15, 1988") and multiple date formats. IP address detection excludes the broadcast and zero addresses.

11
Shipped 3 Jun 2026

The tool had no way to detect emotionally vulnerable users or coercion.

A voice assistant may receive transcripts where the user is in emotional distress or is being pressured by a third party. Neither state was detectable and both require very different assistant responses than a straightforward PII redaction.

Fixed by adding two new intent categories. The emotional distress signal (high, 70% confidence) catches hopelessness, worthlessness and giving-up language. The coercion or pressure signal (high, 65% confidence) catches phrases that suggest the user is being forced to say or do something. Both trigger specific guidance to the assistant.

12
Shipped 3 Jun 2026

Detection had no confidence values. Every finding looked equally certain.

The original engine returned binary findings with no indication of how confident the detection was. A phone number match near a card number was treated with the same certainty as a Luhn-verified card. This made the risk score misleading and offered no way to tune sensitivity.

Fixed by adding confidence: float to every Finding. The risk score is now computed as severity_points × confidence, so a 70%-confidence high finding contributes 25 points rather than 36. The web app shows a CSS confidence bar and percentage on every finding card.

13
Shipped 3 Jun 2026

The web app had no way to see which words in the original transcript were flagged.

The existing "Protect" view showed a cleaned transcript, but there was no visual way to understand which specific words or phrases triggered each finding. Users had to read the finding descriptions and mentally match them back to the original text.

Fixed by adding an Inspect tab to the Check panel. It renders the original transcript with inline <mark> highlights: amber for medium, red for high, brighter red for critical. Each mark is hoverable and shows the finding label, confidence and explanation in a native tooltip.

14
Shipped 3 Jun 2026

Analyzing a multi-turn conversation required calling the API once per turn with no aggregation.

Real voice assistant interactions span multiple turns. The old API had no way to analyze a sequence of utterances together or understand the cumulative risk across a session.

Fixed by adding analyze_conversation(utterances) to the Python API and a Conversation mode toggle to the web app. Each turn is analyzed independently. The result includes a peak decision, cumulative score and the union of all entity kinds seen across the session. A conversation timeline view shows all turns with their individual findings.

15
Shipped 3 Jun 2026

There was no way to copy or export the analysis result.

The safe transcript could only be read on screen. Developers building voice pipelines had no way to programmatically access the full analysis output from the web app.

Fixed by adding a Copy button (clipboard, Cmd/Ctrl+Enter shortcut) and an Export JSON button that downloads a structured file with the decision, score, findings with confidence, redaction map and guidance.

Phase 0.4, 15 June 2026

Saved export protection

16
Shipped 15 Jun 2026

Saved exports could keep sensitive values in plain JSON.

VoiceSafeKit intentionally keeps the transcript readable in memory while filtering because the detector rules need plain text to find emails, SSNs, IBANs, passwords and safety signals. The saved JSON file was different. Once it landed on disk, it could keep the redaction map and other sensitive details readable.

Fixed by encrypting saved analysis files with AES-256-GCM and a key made from the export passphrase. Browser export now uses the Web Crypto API and a local export key. The CLI --out path encrypts by default with VOICESAFEKIT_EXPORT_KEY. There is also voicesafekit decrypt for opening an encrypted export again. TLS/HTTPS still protects network traffic. It does not encrypt local files on disk.

17
Implementation note

The encryption path had to keep the local-first design intact.

The detector still works on readable transcript text in memory, because that is the only way to find and redact sensitive values. The storage boundary is where the new protection starts: before a result is downloaded or written to disk, the full analysis payload is wrapped into an encrypted export object.

The browser path derives an AES-GCM key from the local export key with Web Crypto, then stores only salt, nonce, iterations and ciphertext in the JSON file. The Python CLI mirrors the same idea with the cryptography package, encrypted --out by default, --plain-out for an explicit local debug file and voicesafekit decrypt for intentional recovery.

Phase 0.5, 7 November 2026

Voice-native detection

18
Shipped 7 Nov 2026

Spoken PII went straight through. Every spoken card number came back SAFE.

Speech-to-text often writes what people say, not what they mean: four two four two four two four two ..., alex dot rivera at gmail dot com, oh seven seven double oh nine .... Every rule in VoiceSafeKit was written for digits and symbols, so a spoken card number, SSN, phone number, email, PIN or one-time code was marked SAFE. The same is true of most regex and NER PII tools.

Fixed with a spoken-form normaliser that runs before detection. It rewrites digit words, "oh", "double" and "triple", "plus four four", tens and hundreds, spoken emails and spoken dates into written form, and keeps a character map back to the original. Detection runs on the written form; redaction still applies to the words the person said. Findings caught this way are marked caught in spoken form in the app.

19
Shipped 7 Nov 2026

Ordinary requests were flagged, and one real password was missed.

Testing with everyday assistant requests showed false alarms: "build an emergency fund" was BLOCKED as an emergency, "call Sue" was a legal request, "secret ingredient" and "reset my password" were treated as secrets, and dates such as 2026-11-07 or passport numbers were read as phone numbers. Meanwhile "my password for netflix is hunter22" was missed completely.

Fixed by tightening each rule around how people actually speak: emergency excludes phrases like "emergency fund", "sue" only counts as a verb, secrets need a value that looks like a credential, phone matches that look like dates are dropped, and password phrases allow "for my bank" before the value.

20
Shipped 7 Nov 2026

Some card numbers were only partly redacted.

The payment card pattern used a lazy quantifier, so when a number was grouped unusually it could stop after 13 digits and leave the last few digits in the "safe" transcript.

Fixed by matching the full 13-19 digit number greedily. The SpokenPII benchmark now checks that at least 90% of every sensitive span is masked, so a partial redaction counts as a failure.

21
Shipped 7 Nov 2026

Common voice-channel secrets had no detector.

PINs, one-time verification codes (the classic step in an account-takeover scam), passport numbers, UK National Insurance numbers, SSNs said without dashes, API keys, self-introduced names and UK postcodes were not detected.

Added all eight. The new rules redact only the value, so the assistant still sees "my pin is [PIN removed]" and understands the request.

22
Shipped 7 Nov 2026

Redaction broke agents that need to say the value back.

Replacing an email with [email removed] keeps it away from the model, but then the agent cannot say "I've sent it to your email address" with the real address.

Fixed with reversible placeholders. PrivacySession swaps values for [EMAIL_1], [CARD_1] and so on, keeps the map in memory only, and restores them in the model's reply, including streamed tokens that split a placeholder in two. The same value gets the same placeholder for the whole conversation, whether it was spoken or written. Passwords, PINs, CVVs, one-time codes and API keys are never stored, so the voice can never read them back.

23
Shipped 7 Nov 2026

There was no drop-in path for the voice frameworks people use.

Only an OpenVoiceOS-style helper existed. The most-used open-source voice agent frameworks, Pipecat and LiveKit Agents, had no input-side privacy filter at all.

Added Pipecat processors (filter before the user aggregator, restore before TTS, guard before the assistant aggregator, with on_decision and on_block events) and a LiveKit VoiceSafeAgent that protects each user turn and restores values in tts_node. Both are tested against the real frameworks in CI.

24
Shipped 7 Nov 2026

There was no evidence the tool worked on real speech.

Claims about catching spoken PII meant little without a measurement, and no public benchmark measures PII the way speech-to-text writes it.

Added SpokenPII: 540 labelled sentences in written and spoken form plus 40 tricky no-PII requests, and SpokenPII-ASR, where the scripts are read aloud by a TTS voice and transcribed by Whisper. Results are below, next to Microsoft Presidio.

25
Shipped 7 Nov 2026

The browser app and the Python library could drift apart.

The live app carries its own JavaScript copy of the rules, so every Python change risked the demo showing different results.

The browser engine was ported line for line, then checked against Python on 7,650 inputs (every test case, every sample and 8,000 random spoken strings). Decision, score, every finding span, spoken flags and the safe transcript matched on all of them. The core Python package also now has zero runtime dependencies; encrypted exports moved to an optional extra.

Phase 0.6, 7 November 2026

Reach and real speech

26
Shipped 7 Nov 2026 · Issue #6

Real Whisper output punctuated numbers like lists, and 7 of 108 values leaked.

The first real-speech benchmark showed Whisper writing one spoken card number as 3790, 4339, 7110, 7181, gluing keywords to digits (SSN609507896), turning digits into decimals and hearing "PIN" as "fin".

Fixed by joining punctuated digit groups that follow a sensitive word, allowing keywords glued to digits, and treating "fin" as PIN when digits follow. Years, prices, room numbers and scores stay untouched, and a test checks that they do.

27
Shipped 7 Nov 2026 · Issue #7

In Pipecat, a card number split across two STT frames leaked its first digits.

Many STT services send several final transcriptions per turn. Each frame was checked alone, so "my card number is four two four two" went through and the rest was labelled a phone number.

Fixed by holding a fragment that ends mid-number near a sensitive word for up to 0.8 s and merging it with the next frame. Ordinary speech is never held.

28
Shipped 7 Nov 2026

Only voice-framework users could use it.

Most people running LLMs on their own data do it behind Open WebUI or a LiteLLM proxy. Neither had a spoken-PII filter.

Added an Open WebUI Filter Function you paste into the admin panel, and a LiteLLM custom guardrail. Both swap values for placeholders before the model and restore them in the reply, streamed or not. The LiteLLM guardrail was tested on a running proxy: the model only ever saw [CARD_1].

29
Shipped 7 Nov 2026

The transcript was clean but the call recording still held the card number.

Audio redaction is a paid enterprise feature on the big speech platforms.

Added voicesafekit bleep: findings are mapped to word timestamps and those spans are beeped or silenced in the WAV file, with standard-library code. Transcribing the bleeped file with Whisper finds no card or PIN digits.

30
Shipped 7 Nov 2026 · Issue #9

The real-speech score had been tuned on, so it no longer proved anything.

Once the 7 misses were fixed, the first real-speech set scored 108/108, but only because the fixes were written against it.

A new held-out set (new scripts, the British Daniel voice, Whisper small.en) was transcribed before any change and scored once: 106/108 protected, 1/40 false alarms. The three failures are published as issue #9.

SpokenPII benchmark

How much better it is, measured

Spoken PII protected 100% vs 21%

VoiceSafeKit 0.5 against Microsoft Presidio on 270 spoken PII sentences (synthetic set). With spoken mode off, VoiceSafeKit gets 11%.

Held-out real speech 98% vs 65%

108 utterances spoken by a new voice and transcribed by Whisper small.en, frozen before any 0.6 change. v0.5 scored 94% on the same set.

False alarms on ordinary requests 2% vs 42%

Requests like "set a timer for twenty five minutes" and "call Sue". Speed: 0.06 ms per sentence against about 3 ms.

The synthetic set was written by the same author as the detector, so it works as a regression suite rather than proof. Presidio was run with its defaults and is not built for speech. The held-out misses (a PIN written as money, a comma before a birth year, a mangled date read as a phone) are tracked in issue #9. Everything is reproducible from benchmarks/ in the repo.
